# 0010: 家計簿の仕訳ルール(移動の符号・収入ラベル・貸し借り)

- ステータス: 承認
- 日付: 2026-11-04

## 背景
ADR 0004 で家計簿を複式簿記で記録すると決めた。画面入力から仕訳への変換規則(spec §5.3)のうち、移動の金額の符号と収入ラベルの扱いが未確定だった。あわせて、貸し借りの勘定の持ち方と精算の入力方法も決める必要があった。

## 検討した選択肢
**移動の金額の符号**
- 正の数で入力する: 向きは移動元・移動先だけで決まり、間違えにくい / Notion版と入力が変わる
- 移動元から見た符号で入力する(現行どおり): Notion版と同じ感覚 / 向きを決める要素が2つ(符号と移動先)ある
- どちらでも受け付けて絶対値で扱う: 入力に寛容 / 入力ミスに気づけない

**収入ラベルの扱い**
- ラベルに種別(支出/収入)を持たせ、符号は自由: 会計として正しく、返金も表せる / ラベル作成時に種別を選ぶ手間
- 種別あり、符号が種別と逆なら要確認: 符号ミスに気づける / 返金のたびに要確認が出る
- 種別なし(収支ラベル1種類): Notion版に近い / 収入合計・支出合計を分けにくい

**貸し借りの勘定**
- 相手ごとに貸付金と借入金の2つ: 教科書どおり / 同じ相手との貸しと借りが相殺されない
- 相手ごとに1つ: 未精算額が1つの数字で求まる / spec §5.2 の receivable・payable をまとめる変更が要る

**精算の入力**
- 同じラベル(貸す・借りる)+符号: 操作感が今と同じで、変換規則が1本で済む / 「貸す +x = 回収」の読み方に慣れが要る
- 精算専用の操作: 意味が明確 / 操作の種類が増える

## 決定
- 移動の金額は**移動元から見た符号**で入力する(`-x` で移動元から移動先へ x 移る)。
- ラベルは**支出(`expense`)・収入(`income`)の種別を持ち、金額の符号は自由**とする。
- 貸し借りは**相手ごとに1つの勘定(`loan`)**とする。残高が正なら貸している、負なら借りている。
- 精算は**同じラベル+逆の符号**で入力する。
- その結果、開始残高以外のすべての操作が「口座側 = 入力金額 x、相手側 = -x」という1つの公式で変換できる。

## 結果
- 変換規則が単純になり、テストしやすい。画面の操作感は Notion版と同じになる。
- spec §5.2 の receivable・payable は `loan` 1種類にまとめる。
- 「貸す +x」と「借りる +x」は同じ仕訳になるため、どちらで入力したかは取引の種別(ADR 0013)で区別する。
- 移動の符号の取り違えはDBでもアプリでも検出できない(どちらの符号も正しい入力のため)。画面で向きをわかりやすく表示する必要がある。
