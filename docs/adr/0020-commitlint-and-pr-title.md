# 0020: commitlint でプルリクエストのタイトルを検査する

- ステータス: 承認
- 日付: 2026-11-04

## 背景
フェーズ2(Issue #18)で、コミットメッセージが Conventional Commits の形式かどうかを、commitlint で機械的に検査することにした。

- main は Squash and merge だけを許可している(ルールセット)。そのため、main に残るコミットメッセージは、作業ブランチの個々のコミットではなく、Squash したときの1つのコミットのメッセージになる。
- リポジトリの設定 `squash_merge_commit_title` が `COMMIT_OR_PR_TITLE` になっていた。この設定では、コミットが1つだけのプルリクエストを Squash すると、プルリクエストのタイトルではなく、そのコミットのメッセージが既定のタイトルになる。
- CONTRIBUTING.md の種類(type)の表は6種類だったが、履歴では `build`・`ci` も使われていた。

## 検討した選択肢
**何を検査するか**
- プルリクエストのタイトルを CI で検査し、Squash の既定のタイトルを `PR_TITLE` にする: 検査したものが必ず main に入る / リポジトリの設定を変える必要がある
- 設定は変えず、プルリクエストの中のすべてのコミットを CI で検査する: 設定を変えずに済む / 途中の作業コミットにも形式を求めることになる
- 何も変えない: 手間がない / コミットが1つのプルリクエストでは、検査していないメッセージが main に入りうる

**手元の Git フック(commit-msg)**
- 入れない: 依存関係と仕組みが増えない / 作業ブランチのコミットの形式の誤りに、手元では気づけない
- lefthook・husky で入れる: コミットした瞬間に気づける / 依存関係が増える。`--no-verify` で迂回できるので、結局 CI の検査が必要になる

**範囲(scope)**
- 一覧に限定し、省略も許す: 表記の揺れを防げる / パッケージを増やすたびに一覧を直す必要がある
- 一覧に限定し、必須にする: どこの変更か必ずわかる / どこにも当てはまらない変更で困る
- 限定しない: 設定が要らない / 表記の揺れを防げない

**種類(type)**
- `@commitlint/config-conventional` の11種類をそのまま使う: 標準の設定と一致する / 覚える種類が増える
- 実際に使っている8種類(6種類と `build`・`ci`)、または6種類に絞る: 迷いが少ない / 標準から外れ、自分で上書きする設定が増える

**CI での検査の方法**
- commitlint の CLI を自分で実行する: 手元と同じ設定・同じ道具で検査でき、仕組みが見える / `pnpm install` の分、時間がかかる
- 外部のアクション(amannn/action-semantic-pull-request など)を使う: 短く書けて速い / commitlint とは別にルールを書くので二重管理になり、中身が見えにくい

**ブランチ名の形式**
- 検査しない: Squash するとブランチ名は main に残らない。仕組みが増えない / 命名の約束は人の注意に任せる
- CI で検査する: 約束を仕組みで守れる / 自前の正規表現のジョブが増え、道具が自動で付けた名前が失敗する

## 決定
- **プルリクエストのタイトルを CI で検査する**。ワークフローは ci.yml と分けて `.github/workflows/pr-title.yml` に置き、ジョブ名は `pr-title` とする。`edited`(タイトルの編集)と `synchronize`(新しいコミットのプッシュ)でも再検査する。
- タイトルは環境変数で渡し、`printf` で標準入力から commitlint の CLI に読ませる。シェルのコマンドには埋め込まない。
- Squash の既定のタイトルを **`PR_TITLE`** にする(リポジトリの設定)。
- 手元の Git フックは**入れない**。ブランチ名は**検査しない**。
- 種類は **config-conventional の11種類**をそのまま使う。
- 範囲は**一覧に限定し、省略も許す**。一覧は `repo`・`config`・`deps` と、パッケージ・モジュール・アプリの名前とする。
- 設定は `packages/config/commitlint.config.js` に置く。形式に合う例・合わない例のメッセージで、ルールが効くことをテストで確かめる。

## 結果
- 形式に合わないタイトルのプルリクエストは、`pr-title` を必須チェックにすることで、マージできなくなる。
- 作業ブランチの個々のコミットは検査しない。main には残らないので、形式は人の注意に任せる。
- パッケージ・モジュール・アプリを足したときに範囲の一覧を直し忘れると、テストが失敗して気づける。
- タイトルを編集するたびに、依存関係のインストールを含むジョブが1つ動く。
- 詳細は学習ノート([commitlint と Conventional Commits](../learning/commitlint.md))にある。
