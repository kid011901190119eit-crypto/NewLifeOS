# 0008: 開発はTDDで進める

- ステータス: 承認
- 日付: 2026-11-04

## 背景
コーディングの大部分はAIエージェントに任せる。オーナーがコードを1行ずつ読まなくても、AIが書いたものが正しいかを確認できる仕組みが必要。

## 決定
テスト駆動開発(TDD)で進める。「失敗するテストを書く → 通す最小の実装 → 整理」を繰り返す。

## 結果
- オーナーはテストを読んで「仕様として正しいか」を判断し、AIはテストを通す実装を書く、という役割分担になる。
- テストは仕様書として読めるよう、テスト名を日本語で書く。
- 家計簿のドメインロジックはユニットテストで網羅し(目標90%以上)、DBの制約は本物のPostgreSQLを使った結合テストで確認する。
