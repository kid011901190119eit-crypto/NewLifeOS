# 0001: マイクロサービスではなくモジュラーモノリスにする

- ステータス: 承認
- 日付: 2026-11-04

## 背景
モジュール(家計簿・カレンダーなど)を後からいくらでも追加でき、追加しても既存の部分に影響しない構成にしたい。その手段としてマイクロサービスも検討した。

## 検討した選択肢
- **マイクロサービス**: 境界がプロセス・DBごとに物理的に分かれ、分離は最も強い。一方で、サービス間の整合性、障害の伝播、分散トレースなど運用の負担が非常に大きい。
- **モジュラーモノリス**: 1つのコードベースの中で、モジュールごとにDBスキーマと責任範囲を分ける。開発の負担は小さく、後から一部だけを切り出すこともできる。

## 決定
モジュラーモノリスを採用する。ただし、プロセスは役割ごとに分け(web / api / mcp / worker)、コンテナとして別々に動かす。

## 結果
- 機能を作るより先にインフラ作業で力尽きる危険を避けられる。
- モジュール境界のルール(他モジュールのテーブルを直接触らない)を守れば、将来の切り出しも容易になる。
- コンテナ化・デプロイ・k8sの学習は、この構成でも十分に行える。
