# Prettier(コードの整形)

## それは何か

**Prettier** は、コードの見た目(改行の位置、インデント、引用符、末尾のカンマなど)を、決まった形に自動で書き直す道具(フォーマッター)である。設定できる項目をわざと少なくしていて、「どう書くか」で迷ったり議論したりしなくて済むようにしている。

ESLint との役割分担は次のとおり。

| 道具 | 見るもの |
|---|---|
| Prettier | 見た目だけ。動きは変えない |
| ESLint | バグになりやすい書き方とルール違反。見た目は見ない |

今回使う ESLint の推奨設定には見た目のルールが入っていないので、2つがぶつかることはない。そのため、両者の衝突を防ぐ `eslint-config-prettier` は入れていない。

## なぜ必要か

- 人やエージェントによって書き方がばらつくと、プルリクエストの差分に「意味のない変更」が混ざり、読みにくくなる。
- 見た目を機械に任せると、レビューで中身に集中できる。

## このプロジェクトでどう使うか

### 設定

- `packages/config/prettier.config.js`: 共通の設定。`printWidth`(1行の最大文字数)だけを 100 にして、ほかは Prettier の既定のまま(ダブルクォート、文末のセミコロンあり)。既定の 80 では、既存のコードの関数の宣言が折り返されてしまうため 100 にした。
- `prettier.config.mjs`(ルート): 共通の設定を読み込むだけ。ルートの package.json は `"type": "module"` ではないので、ES モジュールとして読ませるために拡張子を `.mjs` にしている。
- `.prettierignore`(ルート): 対象外のファイル。

### Markdown は対象外

Markdown(`*.md`)は整形しない(Issue #8 で決めた)。対象にすると、既存のドキュメント36ファイルが一度に変わり(見出しの後の空行、表の列幅など)、差分が大きくなるため。入れる場合は、整形だけの別のプルリクエストで行う。

`pnpm-lock.yaml` も対象外にしている。pnpm が自動で作るファイルなので、人が書き方をそろえる意味がない。

### コマンド

- `pnpm format`: ファイルを整形して書き換える
- `pnpm format:check`: 整形が必要なファイルがあれば失敗する(書き換えない)。CI ではこちらを使う予定

Prettier はリポジトリ全体を一度に見る道具なので、パッケージごとではなく、ルートのタスク(`//#prettier:check`・`//#prettier:write`)として Turborepo に登録している。どのファイルが変わったかを Turborepo が判定しにくいので、キャッシュは使わない(`cache: false`)。Prettier 自体が1秒ほどで終わるので、困らない。
