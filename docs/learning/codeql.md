# CodeQL(自分たちのコードの脆弱性の検査)

## それは何か

**CodeQL** は、GitHub が作っている**静的解析**(プログラムを実行せずに、ソースコードを読んで問題を見つけること)の道具である。ソースコードをデータベースに変換し、「外から来た値(リクエストの本文など)が、無害化されないまま SQL や HTML に入る」のような**脆弱性につながるデータの流れ**を、クエリ(問い合わせ)で探す。

| 用語 | 意味 |
|---|---|
| クエリ | 1種類の問題を見つけるためのルール。例: SQL インジェクション、パストラバーサル |
| クエリスイート | クエリの集まり。`default`・`security-extended`・`security-and-quality` がある |
| アラート | 見つかった問題1件。深刻度(Critical・High・Medium・Low)が付く |
| Code scanning | 解析の結果を集めて表示する GitHub の機能。リポジトリの **Security** タブにある |
| SARIF | 解析の結果を表す標準の形式(JSON)。CodeQL も Trivy も、この形式で Code scanning に結果を登録する |

ESLint との違い: ESLint は1つのファイルの書き方(`await` の付け忘れなど)を主に見る。CodeQL は、関数やファイルをまたいで**値がどこから来てどこへ行くか**(テイント解析)を追い、セキュリティの問題に特化している。

## なぜ必要か

- フェーズ5以降で、認証、HTTP の入口、DB への問い合わせなど、外からの入力を扱うコードが増える。入力の扱いの誤りは、レビューで見落としやすい。
- 公開リポジトリなので、脆弱性は誰にでも読める。マージする前に機械で見つけたい。
- 解析のルールは CodeQL 側で増えていく。コードが変わらなくても、新しいルールで古いコードの問題が見つかることがある。

## このプロジェクトでどう使うか

ワークフローは [`.github/workflows/codeql.yml`](../../.github/workflows/codeql.yml) にある。判断の記録は [ADR 0021](../adr/0021-security-scans-and-renovate.md)。

- **ワークフローのファイルで書く**: GitHub の設定画面には、ボタン1つで有効にする「Default setup」もある。このプロジェクトでは、何をしているかが見えるように、ワークフローのファイル(Advanced setup)で書く。両方を同時には使えない。
- **トリガー**: プルリクエスト、main への push、毎週月曜 0:00(日本時間、cron は UTC で書くので `0 15 * * 0`)。
- **`languages: javascript-typescript`・`build-mode: none`**: JavaScript と TypeScript は、ビルドせずにソースコードから解析できる。
- **`queries: security-extended`**: 標準(`default`)より多くのセキュリティのクエリを使う(オーナーが選んだ)。誤検知が出たら、アラートを「誤検知」として閉じる。
- **権限**: 結果を Code scanning に登録するために、このジョブにだけ `security-events: write` を足している。
- **アクションの安全性**: `github/codeql-action` は SHA で固定している。過去に、デバッグ用の成果物に `GITHUB_TOKEN` が含まれる問題(CVE-2025-24362、v3.28.3 で修正)があった。

### マージを止める仕組み

CodeQL のジョブは、**アラートを見つけても成功する**(結果を登録するのが仕事だから)。そのため、ジョブ `codeql` を必須チェックにするだけでは、脆弱性があってもマージできてしまう。

アラートでマージを止めるには、ルールセットの **Require code scanning results** を使う。ツールに `CodeQL` を選び、「Security alerts: High or higher」「Alerts: Errors」のように基準を決める。プルリクエストで新しく増えたアラートが基準を超えると、マージできなくなる。

### アラートを見る

プルリクエストでは、該当する行にコメントのようにアラートが表示される。全体は Security タブの **Code scanning** にある。直したら、次の解析で自動的に閉じる。
